# 启用无忌门户首页

本目录的页面 `/app/portal` **不在 `router.tsx` 中静态注册**,需要通过后端菜单管理动态启用。

## 架构背景

continew 自路由重构后,所有业务页面(dashboard、about、system 列表、app 模块等)**全部**由后端 `/auth/user/route` 接口驱动注册。`router.tsx` 仅保留 `login`、`it-dashboard`、`pwdExpired`、错误页等"框架级"或"含路径参数"的静态例外。

`src/views/app/portal/index.tsx` 已被 `import.meta.glob('../views/**/*.tsx')` 自动发现并准备 lazy 加载,只欠后端菜单一条记录即可上线。

## 启用步骤

### 1. 由系统管理员配置菜单

登录 continew → 进入 **`/system/menu`(系统管理 → 菜单管理)** → 点击 **新建菜单**,填写:

| 字段 | 值 |
|------|-----|
| 菜单类型 | 菜单 |
| 上级菜单 | 根据需要放在「App 应用」或顶级菜单下 |
| 菜单名称 | 门户首页(或自定义,如「员工门户」) |
| 路由地址 | `/app/portal` |
| 组件路径 | `app/portal` |
| 图标 | `home`(或自选 lucide 图标) |
| 排序 | 自定 |
| 状态 | 启用 |
| 是否外链 | 否 |
| 是否隐藏 | 否 |

保存后,**给目标角色授权**(角色管理 → 编辑 → 菜单权限 → 勾选「门户首页」→ 保存)。

### 2. 用户访问

被授权角色的用户:**重新登录** 或 **刷新页面**(`AppRouter` 每次 mount 都会重新拉取 `/auth/user/route`),侧边栏即出现「门户首页」入口,点击或直接访问 `http://<host>/app/portal` 即可。

## 常见问题

**Q: 访问 `/app/portal` 出现 404?**
A: 后端菜单没配置,或者用户角色没被授权。检查菜单管理是否有该记录,以及当前用户角色是否勾选了该菜单。

**Q: 配置了菜单但侧边栏没出现?**
A: 浏览器刷新或重新登录 —— 路由表是每次 mount 时拉取的,`dynamicRoutes` store 不持久化。

**Q: 想改门户的路径为 `/portal` 或其他?**
A: 改菜单里的「路由地址」字段即可,无需改前端代码。但「组件路径」必须保持 `app/portal`(与 `views/app/portal/index.tsx` 文件位置一致)。
